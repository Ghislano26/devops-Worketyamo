3. Rebase : rejouer ses commits sur une nouvelle base

Même situation que l'exercice précédent, mais on veut un historique linéaire, sans commit de fusion. Regardez les commits C4 et C5 être recréés (C4', C5') : leur empreinte change.

📌 À retenir

  • git rebase main (depuis feature) rejoue les commits de feature au-dessus de main : ce sont de nouveaux commits (C4').
  • Les anciens commits restent visibles en pointillés (orphelins) : ils existent encore, ils ne sont plus référencés.
  • Règle d'or : ne rebasez jamais une branche que d'autres utilisent.
